Unit 01

Overview of PM & SPM

  • Project: งานชั่วคราว มีเป้าหมาย/ผลลัพธ์เฉพาะ ใช้เวลา เงิน ทรัพยากรจำกัด; 4 ลักษณะ: Uniqueness · Temporary · Highly Complex · ใช้ทรัพยากรมาก
  • PM: ประยุกต์ความรู้/ทักษะ/เครื่องมือ บรรลุเป้าหมายอย่างมีประสิทธิภาพและประสิทธิผล; Planning, Organizing, Leading, Motivating, Controlling
  • โครงการ / งานประจำ: จำกัดเวลา/ต่อเนื่อง; ทรัพยากรใช้แล้วคืน/ใช้ต่อ; ทีมเปลี่ยน/คงตัว; ต้องใช้คนชำนาญ/มีเวลาฝึก; ต่อรองและขัดแย้งสูง/ต่ำ
  • Triple Constraint: Scope · Time · Cost สัมพันธ์กัน เปลี่ยนด้านหนึ่งต้องปรับด้านอื่น มิฉะนั้นกระทบ Quality
  • วิชาชีพ: สหวิทยาการและงานเบ็ดเสร็จ; PMI = Project Management Institute; PMBOK = Project Management Body of Knowledge
  • PMBOK 10 หมวด: Integration · Scope · Time · Cost · Quality · Human Resource · Communications · Risk · Procurement · Stakeholders
  • ที่มา/ความสำคัญ: Strategic Intent, Vision, Mission สู่การปฏิบัติ; Top-down = นโยบาย/กลยุทธ์ผู้บริหาร; Bottom-up = ปัญหางาน/โอกาส/พัฒนาหรือสินค้าใหม่
  • เชิงรับ / เชิงรุก: รับ: ลูกค้าเปลี่ยน เทคโนโลยีก้าวหน้า ปัญหาบริหารซ้ำ ทรัพยากรจำกัด; รุก: คุณภาพดีขึ้น เตรียมวิกฤต เร็ว/ถูกต้อง สินค้าใหม่/Value Creation
  • ลูกค้า/ปัญหา: เดิมต้องดี ตรงเวลา ถูก ครบ; ปัจจุบันดีกว่า เร็วกว่า ถูกกว่า เกินคาด; ปัญหา: Late/Fail ไม่ตรงคาด Quality/Reliability ต่ำ Over Budget
  • โครงการ 5 ประเภท: วิจัย/ทดลอง = สมมติฐานและตัวแปร; ทฤษฎี = บูรณาการแนวคิดเชิงลึก; สิ่งประดิษฐ์/นวัตกรรม = ผลงานใหม่; สำรวจ = ข้อมูล/พื้นที่จริง; พัฒนาธุรกิจ = สถิติ ผู้บริโภค ปัจจัยจุลภาค/มหภาคและความร่วมมือ
  • SPM: วางแผน/นำโครงการสร้างซอฟต์แวร์ตรงผู้ใช้และคุณภาพภายใต้ต้นทุน; แก่น: Manage งาน · Allocate ทรัพยากร · Timing
  • ความท้าทาย/Trade-offs: จับต้องไม่ได้ เห็นผลกระทบยาก; กระบวนการขึ้นกับองค์กร; โครงการ/เทคโนโลยีต่างกัน ประสบการณ์เก่าอาจล้าสมัย; Requirements เปลี่ยนกระทบเวลา/งบ/Quality; คู่แลก: คุณภาพ/น่าเชื่อถือ · สมรรถนะ/ยืดหยุ่น · สร้างสรรค์/เปิดเผย · โครงสร้าง/กระบวนการ

Unit 02

SPM Process & Methodology

PLC: 5 ระยะ

  • Initiation: นิยาม/เป้าหมาย Feasibility Scope เบื้องต้น มูลค่า Stakeholders Project Charter; ผล: ไปต่อ/ชะลอ/ปฏิเสธ
  • Planning: 15 งาน: Scope · Activity Definition · WBS · Sequence · Duration · Resources · Schedule · Cost Estimate · Budget · Quality · HR · Communication · Risk · Purchase/Acquisition · Contract
  • Execution: Manage Execution · QA · Acquire/Develop Team · กระจายข้อมูล · Select Sellers/ประมูล; จัดทรัพยากร สร้างผลงาน ประชุมแก้ปัญหา
  • Monitoring & Control: 12 งาน: Monitor Project · Change · Scope Verification · Scope Control · Schedule · Cost · Quality · Manage Team · Performance Report · Stakeholders · Risk · Contract Administration
  • Closure: ส่งมอบ/ถ่ายโอน Final Report หลักฐานลูกค้ายอมรับ/UAT บำรุงรักษา/รับประกัน สรุปเงิน คืนทรัพยากร; ปิดได้ทั้งสำเร็จหรือล้มเหลว
  • ระยะทับซ้อน: ไม่ได้จบทีละขั้น; Monitoring ควบคุมต่อเนื่อง Execution มีงานมากสุด; PLC บริหารโครงการ ส่วน SDLC สร้างซอฟต์แวร์ ทำงานสัมพันธ์กัน

SDLC: 7 ขั้น

  • Planning: Objective, Outcome, Time, Scope, Resources, Stakeholders; วางแผนเก็บ Requirements/ออกแบบ/ทดสอบ
  • Requirements: PM + Analyst + Product Owner เก็บ Domain/Functional/Non-functional; Developer/QA ตรวจเพื่อออกแบบและหาข้อจำกัด
  • Design & Prototyping: Architecture · UI/UX · Language · DB · Communication/Security; ได้ System Design Specification ให้ Review
  • Development: Coding · Compile · Find/Fix Errors · Source Code/Version Management; พัฒนาส่วนย่อยรวมเป็นระบบ เอกสารออกแบบดีช่วยเร็ว
  • Testing: Test Cases, Unit/Integration/Functional/Acceptance Test; ไม่ผ่านส่ง Developer แก้; Automated Test ช่วยเร็ว
  • Deployment: Install/Release ในสภาพจริง ฝึกผู้ใช้ ทำ Manual และ Support
  • Operation & Maintenance: Maintenance Plan; Correction · Prevention · Investigation · Improvement/วิเคราะห์ Change Requests

Unit 03

Requirements in Software Project

  • Need / Requirement: Need = เป้าหมาย เช่นดับกระหาย; Requirement = สิ่งที่ต้องทำให้ถึงเป้าหมาย เช่นซื้อน้ำดื่ม (Elgendy 2016)
  • Pyramid: Business = Sponsor/เป้าหมาย/Scope; User = สิ่งผู้ใช้ทำ/Input–Output; System = หน้าที่และคุณภาพอย่างละเอียด
  • Functional / Non-functional / Domain: หน้าที่ระบบ / คุณภาพหรือข้อจำกัด / กฎและเงื่อนไขเฉพาะธุรกิจ; Non-functional: Speed, Security, Portability, Compatibility, Capacity (Storage), Reliability (Failures/Time between Failures), Environment (เวลาทำงาน/สภาพอากาศ), Localization (ภาษา/สกุลเงิน/Time Zones)
  • URS / SRS: URS บอกผู้ใช้ทำอะไร ภาษาธรรมชาติให้ลูกค้า; SRS บอกรายละเอียดระบบ Functional/Non-functional ให้ Developer; 1 URS แตกเป็นหลาย SRS
  • Encoding 5 แบบ: F = Functional · D = Data · B = Behavior/การตอบสนอง · I = Interface/เชื่อมต่อ/ส่วนผู้ใช้ · P = Output
  • Requirement Engineering: 7: Inception ถามเปิด/เข้าใจปัญหา; Elicitation เก็บเป้าหมาย/Scope/ความไม่แน่นอน; Elaboration จัดกลุ่ม/ขยาย/Model; Negotiation แก้ขัดแย้ง; Specification เอกสาร; Validation ตรวจครบ/ชัดโดยทุกฝ่าย; Requirement Management คุมการเปลี่ยน (Jawadekar 2004; หัวข้อสุดท้ายพิมพ์ Validation ซ้ำในสไลด์)
  • Elicitation: 4: เก็บร่วม Stakeholders; จัดโครงสร้าง/ระบบย่อย/ความสัมพันธ์; จัดลำดับ/ต่อรอง/ตัดส่วนไม่จำเป็น; ทำ URS/SRS; จัดกลุ่มตามผู้ใช้หรือส่วนทำงานของระบบ
  • 9 เทคนิค: Documentation Analysis · Focus Group · Interview · Brainstorm · User Interface Analysis · Interface Analysis · Prototyping · Requirements Workshop · Survey/Questionnaire
  • Work Products: รับรองความต้องการ/Feasibility · Scope · กลุ่มลูกค้า/ผู้ใช้/Stakeholders · Technology · Requirements/Constraints · Usage Scenarios · Prototype; วิเคราะห์ต่อเป็น User Requirement, Workflow, Problem Statement, Business Information/Rules
  • การสัมภาษณ์: ถามใครเป็นต้นเรื่อง ใครใช้ ประโยชน์ธุรกิจ/เศรษฐกิจ ข้อมูลจำเป็น; Analyst เป็นคนกลาง ที่ปรึกษา ผู้แก้ปัญหา/ต่อรอง
  • ประโยชน์ 5: Scope/งบชัด · ลดสับสน/ประชุมซ้ำ · เพิ่มคุณค่าธุรกิจ · พบความต้องการแฝง · พัฒนาเฉพาะขอบเขต/เลือกเทคโนโลยีเหมาะ

  • Control: 4 ขั้น: ตั้ง Baseline; วัดงานจริงทางการ/ไม่เป็นทางการ; เทียบความเบี่ยงเบน; Corrective Action ให้กลับแผนด้าน Quality/Time/Cost
  • QA / QC: QA วางแผน/ระบบล่วงหน้าสร้างความมั่นใจ; QC ตรวจผลตามมาตรฐาน/คุณภาพ/ปริมาณ; ตามบทเรียน QC อยู่ใน QA อยู่ใน QMS เพื่อพึงพอใจลูกค้า
  • 3 Baselines: Scope = Scope Statement+WBS+Dictionary; Schedule = Milestones/Critical Path; Cost = งบตามเวลา/ต้นทุนตรง–อ้อม ยอดท้ายคือ BAC; Project Budget = Cost Baseline + Management Reserve
  • EVA — Earned Value Analysis: เทียบแผน งานเสร็จตามงบ เงินจ่ายจริง เพื่อวัด/คาดอนาคต; PV (Planned Value)/BCWS งานควรเสร็จ; EV (Earned Value)/BCWP งานเสร็จจริงคิดด้วยงบ ไม่ใช่รายรับ/กำไร; AC (Actual Cost)/ACWP เงินใช้จริง
  • ค่าคาดการณ์: BAC/Budget at Completion งบแผนรวม; EAC/Estimate at Completion คาดเงินจริงทั้งโครงการ; ETC/Estimate to Complete เงินเพิ่มจากวันนี้; VAC/Variance at Completion คาดต่ำ/เกินงบเมื่อจบ; หน้า11 พิมพ์ PA ให้ใช้ PV
SV = EV − PV; SPI = EV / PV
CV = EV − AC; CPI = EV / AC
  • แปลค่า: SV/CV เทียบ 0; SPI/CPI เทียบ 1; สูงกว่า = เร็ว/คุมเงินดี ต่ำกว่า = ช้า/ต้นทุนสูง; SV/CV หน่วยเงิน ไม่ใช่วัน; SPI/CPI ไม่มีหน่วย หารได้เมื่อ PV/AC ≠0
  • ตัดสินใจ: CPI>1/SPI<1 เพิ่ม Resources/ล่วงเวลา/ติดตาม; ทั้งคู่>1 รักษา/ให้รางวัล; CPI<1/SPI>1 ตรวจเงิน/จัด Resources/ลดส่วนเกิน; ทั้งคู่<1 หาสาเหตุ จัดลำดับ/เพิ่มประสิทธิภาพ ใช้ Software เสนอเพิ่มงบ/เวลา
  • Communication Plan: ใครรับ เรื่องอะไร รายละเอียดเท่าไร เมื่อไร/ถี่แค่ไหน ผ่านช่องทางใด; เลือกตามทางการ/ด่วน/กลุ่ม–ส่วนตัว; Phone/Video/Messenger/PM Software/Email/Face-to-Face; โครงการใหญ่ใช้ Plan เล็กอย่างน้อยข้อมูลติดต่อ

  • Traditional / Agile: Traditional Scope/Cost/Schedule Baseline, SPI/CPI/EAC/VAC, S-curve/Status/Dashboard, รายสัปดาห์–เดือน Formal Change (Fixed-price/Waterfall); Agile วัด Increment/Backlog, Board/Charts/Velocity, Daily/Sprint, Product Backlog Reprioritization (เปลี่ยนบ่อย)
